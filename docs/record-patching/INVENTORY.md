# Skyrim record patching inventory

Inventory reviewed through 2026-10-05. Initial source baseline: `823a8f3`; updated after the record-header, container-inventory, script-adapter metadata, name-translation and partial-override fixes and the [keyword, PHZD and inherited-audit fixes](REVIEW.md#coverage-fix-verification); Mutagen Skyrim `0.54.4`. This is the evidence inventory for later user documentation, not a set of detailed record guides. It describes the current registrations, decision boundaries, exceptions, and omissions. “Active” means reachable through the normal patching entry point when that record family is enabled; it does not mean every record receives an override.

## General behavior

- The ordinary unit of patching is a **registered property**, not an entire record and not every leaf exposed by Mutagen. Dotted registrations are separate decisions. A registered aggregate is one decision for its contents unless explicitly split. Unregistered fields are not independently conflict-resolved. Overrides start from a selected source record through Mutagen's override-copy path; child groups and generated serialization data are subject to Mutagen's copy/write rules.
- Ordinary values are processed from oldest to newest eligible override. A value different from both the original and current proposal replaces the proposal. A return to the original value requires the current owner to be a declared or configured virtual master. Thus an unrelated later plugin carrying an original value does not automatically erase an earlier change. “Atomic” below uses this selection rule; it does **not** simply mean “take the load-order winner.”
- Collections can merge individual rows, and flag fields can merge individual registered bits. Row deletion, replacement, restoration, order, and nullable-list presence use the corresponding ownership rules; special row handlers are called out below. List entries are generally complete values, not recursively merged objects. Whole-list atomic values have a single owner for the entire sequence/dictionary, including embedded data.
- Ignored plugins are removed from the decision chain. Record families can be disabled. The initial filter skips a vanilla effective winner, chains of at most two eligible versions, and chains whose immediately preceding version is vanilla. Tamriel's special CELL policy can bypass that initial filter. Malformed contexts can be skipped while loading.
- **Actual priority-policy limit:** `ShouldBreakEarly` runs before the shared record handler. It does not inspect priority-mod or EditorID policy settings. Consequently those policies cannot affect ordinary records already removed by that filter. For records that reach the handler, a configured always-win source bypasses individual property merging and is copied through the record override path; the last matching configured priority source wins. If it is already the effective winner, no override is emitted. The handler also exits on a vanilla winner before applying this priority rule.
- EditorID offers normal forwarding, suppression of EditorID-only overrides, or preservation of the latest configured official baseline's EditorID. The latter two act after/within the shared handler and have the prefilter limitation above. Official-baseline membership is configurable, including Creation Club treatment.
- Only decisions different from the effective winner are applied in the ordinary path. Context insertion and property application are staged against detached targets and copied mutable ancestry. Setter exceptions or structured handler errors discard the candidate, preserving existing output records and siblings. Other records continue for diagnostics, but any run error blocks Synthesis/desktop publication. Non-null writes are checked with each handler’s semantic comparer; existing null/default normalization is retained. This establishes failure isolation, not a guarantee of game-valid output for every input. See [verification](REVIEW.md#partial-override-fix-verification).

### Shared property conventions

| Surface | Actual decision boundary / limitation |
|---|---|
| `EditorID` | Registered in every concrete handler. Shared policy above. |
| Record-header flags | All 122 handlers register only the composite `MajorRecordFlagsRaw` header path. It merges owned bits from base, common Skyrim and applicable record-specific enums with one owner per bit; alias setters cannot reintroduce selected clears. |
| Composite header path | Every header uses the approved integer flag handler. Applicable inherited GLOB and PHZD enums are included; NAVM bit 31 retains its unsigned bit pattern. Bits outside the configured mask remain winner-owned. |
| Other flag registrations | Registered flags get per-bit ownership through flag handlers. Nullable flags also track presence separately. Unknown-bit handling depends on the constructor/options and setter: do not promise universal preservation or universal merging of unknown bits. Flags inside an atomic aggregate travel with that aggregate. |
| Text and assets | Many plain strings compare with trailing whitespace removed; asset paths have path-aware normalization. Translated names retain an `ITranslatedStringGetter` throughout selection and use `TranslatedStringReflectionPropertyHandler` to deep-copy the target language and all available translations as one value. Comparison uses Mutagen's default-language or all-language comparer according to `TranslatedString.DefaultLanguageComparisonOnly`, without trimming text. Translation-only differences do not trigger forwarding in default-language mode, but a selected name still carries all its translations. Optional null names remove the value; CLAS/EYES/FLOR/KEYM required null names become empty in Mutagen's configured default language. MATT Name uses plain-string scalar reflection. |
| Ordinary models and icons | `Model`, model-valued properties, and `Icons` are whole values. Model alternate textures are inside the whole model, except ARMA's explicitly split models. Ordinary `ModelHandler` compares/copies model data bytes and ordered alternate textures too. Icons contain their paths together. |
| `ModelAndBounds` | Conditional coupling: an accepted model filename/geometry change takes `ObjectBounds` from that same override. Bounds-only changes can still forward separately. This is **not** unconditional whole-group atomic selection. Model contents remain a whole model value. |
| `WorldModelAndBounds` (ARMO) | The same conditional rule for the gendered armor world model and bounds; the model side is the whole male/female model-and-icon aggregate. |
| `ObjectBounds` alone | One complete bounds value, not independent min/max or coordinate edits. |
| `Destructible` | One complete structure, including its data, stages, and nested models/links. Not a stage-list merge. |
| Scripts exposed as a list | The matrix labels these `K: VirtualMachineAdapter` or `K: VirtualMachineAdapter.Scripts`. Scripts match by name; each script's flags and complete properties are one authored value. Script properties/arrays are not individually conflict-merged. Papyrus unused bytes do not drive script equality; selected copies preserve destination unused values where the policy supports them. |
| Ordinary list-style VMAD setters | `AbstractVirtualMachineAdapterHandler` replaces scripts while preserving the destination Version/ObjectFormat, including a present-empty destination. Only creation without a destination uses Mutagen defaults (5/2). Null removes the adapter except for MGEF's existing specialized setter, which creates a default empty adapter. INFO/PACK/PERK use aggregate adapters; QUST/SCEN have explicit metadata decisions. |
| Binary payloads | Registered byte slices/opaque blobs are whole values, never element-wise merges. Their gameplay interpretation is not established merely by having a handler. |
| Omitted metadata | Form identity, version-control metadata, generic runtime/registration members, and binary translators are not independent property decisions. Explicit serialization-state exclusions and child containers are listed separately below. An exclusion from decision-making does not establish byte-for-byte preservation after serialization. |

Shared sources: [ModelBoundsHandler](../../DreadsMashedPatch/PropertyHandlers/General/ModelBoundsHandler.cs), [ModelHandler](../../DreadsMashedPatch/PropertyHandlers/General/ModelHandler.cs), [WorldModelHandler](../../DreadsMashedPatch/PropertyHandlers/Armor/WorldModelHandler.cs), [AbstractDestructibleHandler](../../DreadsMashedPatch/PropertyHandlers/Abstracts/AbstractDestructibleHandler.cs), [AbstractScriptListPropertyHandler](../../DreadsMashedPatch/PropertyHandlers/Abstracts/AbstractScriptListPropertyHandler.cs), [AbstractVirtualMachineAdapterHandler](../../DreadsMashedPatch/PropertyHandlers/Abstracts/AbstractVirtualMachineAdapterHandler.cs), [TranslatedStringReflectionPropertyHandler](../../DreadsMashedPatch/PropertyHandlers/General/TranslatedStringReflectionPropertyHandler.cs), [MajorRecordFlagsRawHandler](../../DreadsMashedPatch/PropertyHandlers/General/MajorRecordFlagsRawHandler.cs).

## Record and property matrix

Every active or dormant record handler appears below. Names are the actual registered keys so future documentation can be checked against code. Shared `EditorID` and composite `MajorRecordFlagsRaw` are omitted; `MajorFlags` and `SkyrimMajorRecordFlags` are header aliases covered by that shared registration, not separate keys. Each name in “Individual” is independently selected; vectors/colors/enums in that column are still single values, not component-wise edits. Each name in “Whole values/groups” is independently atomic, **not** one group spanning the entire cell of the table. `ModelAndBounds` and `WorldModelAndBounds` are the conditional exception explained above. A whole aggregate includes all its nested collections unless an exception is stated later.

`EditorID` and common record-header registrations are omitted from the cells because they follow the shared conventions above. Record-specific flags remain listed. A dash means no registration in that category.

Collection modes:

- **K — keyed:** rows identified/sorted by a key; duplicate occurrences can be retained. Not a whole-list merge.
- **O — aligned ordered:** rows align across versions while preserving meaningful order. Not a whole-list merge.
- **P — positional:** each ordinal is a separate complete row value; no key matching or sequence alignment. Not a whole-list merge.
- **A — atomic:** complete collection/dictionary selected as one value.
- **S — specialized:** IPDS's material mapping policy described below.
- **U — unordered:** shared unordered list handling; currently appears only in the dormant LAND handler.

Record ownership boundaries later in this inventory take precedence over these local property/list modes. `Excluded` rows describe dormant code only; **none of their listed properties is forwarded by the normal run**.

## Whole-record ownership boundaries

A semantic change in any trigger below between adjacent eligible overrides resets **all registered property contexts** to the newer override. That is stronger than making just the named collection atomic. Later overrides can still merge against this new ownership baseline until another trigger changes. Unregistered fields are not assigned contexts by this reset and are not necessarily copied from the triggering source: final output still starts from the effective winner. Therefore “complete record ownership” in code comments must not be documented as a literal whole-record snapshot copy. Priority-mod copying is a separate path.

## Uncertainties and limits for later documentation

| Question | Established behavior / remaining uncertainty |
|---|---|
| PHZD inherited coverage and UDR | The eighteen-field coverage gap is fixed. The original omission rationale remains unknown. UDR coordination is intentionally unchanged because no PHZD-specific UDR policy is established. |
| Why are HAIR, LENS, NAVI, VOLI and the seven placed sibling types not processed? | No independent route was found; supported references and narrowing are listed above. The reason is **uncertain** because there is no matching entry in the explicit exclusion map. |
| Opaque fields and blobs | Whole-value comparison/copy or lack of registration can be established. Their gameplay meaning and whether combining separately registered blobs is semantically safe are **uncertain** where the code only exposes byte payloads. This inventory makes no safety claim for them. |
| Writer preservation | Not independently forwarding a field is established. Exact on-disk preservation of every unused field, missing subrecord, parent container, and version discriminator is **not established** by this inventory. Mutagen copy masks and serialization can change representations. No end-to-end real load-order output was generated for this documentation task. |
| Full nested equality | Atomic ownership is established from the handler/context. It does not prove that every nested member affects comparison: specialized handlers can use restricted equality (for example ARMA filename metadata or Papyrus unused bytes). MGEF's three compared members cover its current semantic subtype surfaces. Do not turn the inventory into a promise that every byte difference triggers forwarding. |
| Null versus empty | Shared nullable-list ownership exists, but setters differ. KeywordListHandler now writes null as absence in all eighteen registrations and preserves present-empty lists, verified through full-run permission cases and binary output for each type. Ordinary non-nullable collections clear to empty, and many aggregates have their own presence rules. Shared post-write validation checks non-null values only; see the [audit](COVERAGE-COMPARISON-AUDIT.md#keywords-selected-absence-is-not-applied). A universal “null removes the field” claim would be incorrect. |

Known discrepancies with older documentation/audits, not uncertainties about the current code:
